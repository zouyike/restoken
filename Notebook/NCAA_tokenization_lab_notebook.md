Construction, as implemented (`restoken/`, 2,633 lines of src):
- **Paired dictionaries, v11, 400 blocks.** `bb_dict_llm_v11.json` (160 KB) is all the LLM ever sees: `id, helm, class, chirality, charge_label, mc_type(alpha|beta|gamma), mc_nmod, mc_len, sc_bulk, polarity_bin, flex_bin, tags`. `bb_dict_backend_v11.json` (352 KB) holds the chemistry: InChIKey, `structure.aa_smiles`/`aa_selfies`, side-chain `smiles`/`selfies`, `hbd`, `hba`, `rot`, `charge`, `aromatic_level`, `halogen`, `stereo`, `rot_total`. Hiding structure from the model *is* the mechanism.
- `library.py` (363) indexes both into a frozen `Block` dataclass. `validator.py` (268) enforces the 7 constraints, including backbone adjacency via `_BACKBONE_ORDER`. `cyclic_assembler.py` (467) maps a token string to cyclic SMILES on the RDKit graph: parse each `aa_smiles`, strip Ac/NMe caps, form inter-residue amides, close the macrocycle. `decomposer.py` (609) is the inverse (real peptide to tokens; drives the MK-0616 / LUNA18 / cyclosporin case studies). `guideline_generator.py` (808) turns markdown guideline files with embedded JSON into constrained sampling plus LLM prompt construction.
- Benchmarks: `experiments/output/{exp1_validity,exp2_controllability,exp3_property_constrained,w3_scaleup,open_model_bench}`; w3 at `n_requested=500` per cell; open-model arm covers gemma-3-4b-it, gemma-3-12b-it, Mistral-Nemo-12B, Mistral-Small-24B, Llama-3.3-70B x 4 constraint profiles.
- **The one trained artifact today** is the permeability judge, not a generator: RoFormer, 6 layers, hidden 768, vocab 586, fine-tuned on CycPeptMPDB PAMPA (train 5,581 / val 620 / test 688), early-stopped at ep25. Test metrics `output/test_metrics.json`: **R2 0.357, RMSE 0.931, Spearman 0.739, Pearson 0.647**. The manuscript quotes only rho = 0.74.
- Applicability domain is already quantified (`output/applicability_domain.json`, `script/applicability_domain.py`): nearest-neighbour Morgan-Tanimoto to the 6,201 training peptides is mean 0.970 / median 1.000 for the held-out test set but mean 0.300 / median 0.291 for the 11,532 ResToken molecules, 54.6% below 0.30. The manuscript handles this correctly - scores are used as relative, and "every contrast above is drawn between equally out-of-domain populations, so any uniform bias of the judge cancels".

Proposed ICLR experiment - **representation-controlled fine-tuning** (PLAN ONLY, not started, awaiting Yike's decision):
- Rationale: every headline number in the paper is zero-shot prompting of frozen models, so at a representation-learning venue the contribution reads as a curated vocabulary plus prompt engineering plus a benchmark. Fine-tuning turns "ResToken is a good *interface*" into the testable claim "ResToken is a good *learning target*".
- Design: one base model, three arms differing **only** in the target string for the identical molecule - ResToken vs HELM vs SMILES. Same molecules, same instruction, same tokens-seen budget, same LoRA config, same decoding. Crossed with corpus size 0 / 100 / 1k / 10k to give a sample-efficiency curve; 12 LoRA runs.
- Data is free and needs no experiment: `CyclicPeptideAssembler` deterministically maps any token sequence to SMILES (already validated on 8,130 molecules), so a paired three-representation corpus of ~50k length 5-8 sequences can be minted on CPU, labelled by RDKit.
- **Anti-circularity rule, mandatory**: train only on rule-computable labels (the 7 validator constraints - charge, HBD, HBA, rotatable bonds, N-Me count, length, backbone adjacency). The permeability judge must never enter the training signal, so predicted permeability stays an out-of-sample generalisation test.
- **Anti-memorisation rule, mandatory**: report constraint satisfaction on held-out constraint *profiles* never trained on, plus novelty (fraction of generations absent from the training corpus) and diversity, otherwise high validity is trivially explained by memorising validator-passing strings.
- Compute: Qwen3.5-9B or Gemma-3-12B (both already in the paper), LoRA bf16 on gpu_cpu 4090D 48 GB; envs `ai`, `gemma3_env`, `llama4` all carry torch+transformers+trl+peft+unsloth. Estimated ~8 GPU-hours plus eval - compute is not the constraint, harness time is.
- Honest prediction, both outcomes publishable: SMILES should improve sharply from its 18.1% zero-shot validity because fine-tuning fixes syntax, so the headline gap will shrink. If ResToken still leads, the claim is far stronger than the zero-shot one. If SMILES converges, the finding becomes "ResToken's advantage is a low-data / zero-shot advantage that supervision erases", which is a clean representation result with a scaling curve. Not sure which will happen - that is the point of running it.
- Risk I will not hide: this raises ICLR odds from roughly 10-15% to maybe 25-30% by my estimate (speculative, no data behind those numbers), it does not fix the venue-fit problem that ICLR 2027 has no Datasets & Benchmarks track, and it competes for the same 21 days as the mandatory LaTeX rebuild.
